# COMP5400 Stigmergic Sorting

This repository contains the code for a COMP5400 Coursework 2 project comparing a hand-designed Deneubourg-style stigmergic sorting method with an evolved neural controller. The task involves agents moving around a two-dimensional arena and sorting coloured pellets into clusters using only local information.

## Project Overview

The project investigates whether a neural controller evolved using a genetic algorithm can produce sorting behaviour comparable to, or better than, a classical Deneubourg-style pickup-and-drop rule. The comparison is based on clustering quality, including purity, number of clusters, and average cluster size.

Two main controller types are implemented:

* **Deneubourg baseline**: a hand-designed probabilistic pickup-and-drop controller based on local pellet similarity.
* **Evolved controller**: a fixed-topology neural controller whose weights are optimised using a genetic algorithm.


## Installation

Create and activate a Python virtual environment:

```bash
python -m venv .venv
```

On Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Install dependencies:

```bash
pip install -r requirements.txt
```

## Running Tests

Run the full test suite from the repository root:

```bash
pytest -q
```

The current test suite checks the main simulation components, metrics, evolution logic, and final experiment utilities.

## Running Experiments

Run the Deneubourg baseline:

```bash
python -m src.experiment --config experiments/configs/baseline.yaml
```

Run the evolved controller experiment:

```bash
python -m src.experiment --config experiments/configs/fitness_default.yaml
```

Run the final head-to-head comparison:

```bash
python -m experiments.m5_runner
```

Run the final analysis script:

```bash
python -m experiments.m5_analysis
```

## Configuration Files

Experiment settings are stored in `experiments/configs/`.

The main configuration files are:

* `baseline.yaml`: Deneubourg-style baseline setup.
* `fitness_default.yaml`: evolved controller setup using the full GA configuration.
* `fitness_quick.yaml`: shorter evolved-controller configuration for quicker testing.
* `sanity.yaml` and `sanity_long.yaml`: smaller checks for simulation behaviour.

## Evaluation Metrics

The project evaluates sorting behaviour using:

* **Cluster purity**: how consistently pellets of the same colour appear within each cluster.
* **Cluster count**: the number of detected pellet clusters.
* **Average cluster size**: the mean size of detected clusters.
* **Fitness score**: a composite score used during evolution to guide the neural controller.

Cluster-based metrics are calculated using a DBSCAN-based method.

## Reproducibility

The project uses seeded random number generation through `SeedBank` to make experiments reproducible. Configuration files specify the main seed and simulation parameters.

## Notes

Generated experiment outputs are written to `experiments/results/`. These files are not required to run the code and may be regenerated by running the experiment scripts.
